# Frozen linked-worktree recovery archives

`legacy-workspace-capture.py` prepares recovery data under an actual `LegacyGate.frozen_view` lock. It does not remove files, edit Git registrations, publish refs, restore archives or expire recovery data. No live legacy gate or reboot acceptance is implied by its disposable tests.

`prepare(gate, id, approved_gate_sha256=..., repo_alias=..., candidate_path=..., scratch_root=...)` requires an exact terminal removal candidate from the approved plan and a private scratch directory. The target must have a distinct linked-worktree Git admin directory. A selected checkout containing another registered checkout is refused. Separate selection and recovery of nested targets must precede any future parent retirement.

The artifact contains `recovery.tar.gz`, `manifest.json` and `receipt.json`. The gzip tar streams every file from the working checkout and its linked Git admin directory. It preserves staged index bytes, current working bytes, untracked files, symlink text and original UID/GID/mode from the gate inventory. Binary xattrs and nanosecond mtimes are recorded in the manifest and `RICHOS.xattrs`/`RICHOS.mtime_ns` PAX fields. A future restore tool must apply these explicit fields; ordinary tar extraction alone is not an xattr restoration guarantee. There is no extraction command in this primitive.

For an explicitly selected `orphan-registration`, the receipt instead records `capture_kind: orphan-admin-only` and `working_tree_bytes_present: false`. Its archive contains only the surviving `git-admin` namespace, including index, lock and custom administration bytes. It preserves the same complete object dependency set without claiming recovery of working files already absent before gating. Existing checkouts use `capture_kind: full-worktree`; a readable registration lock is preserved in that archive. The nearest existing ancestor identity and first absent path component are checked before and after capture and every later validation. Recreated paths or intermediate containers cause refusal.

Every archived file has a SHA256 hash. Archive contents and metadata are read back and compared with the manifest, then the complete source inventory is read again. The receipt binds the archive hash, manifest hash, candidate inode identity, Git common identity and approved gate. Failed verification removes only this operation's private incomplete artifact. Archive creation requires space for potentially incompressible source bytes plus a margin. Compression does not justify overcommitting the remaining disk.

Standard `CACHEDIR.TAG` signatures are reported as classification hints. They never omit files or grant expiry authority. All captures remain `unclassified-retained` with automatic expiry disabled, including apparently clean captures. Working-tree symlinks are preserved without following them. Git admin symlinks are refused before privileged dependency reads because they could redirect an index or ref read outside frozen storage.

The archive is a working/index recovery artifact, not a standalone repository. It excludes the shared canonical object database. Its dependency report lists the terminal commit, current per-worktree HEAD, per-worktree ref endpoints, both sides of reflogs and all staged index objects, resolved-conflict undo objects and cached-tree endpoints. Raw archived split-index bases retain their old entry dependencies too. Unknown index extensions are explicit handoff vetoes, using the [published Git index format](https://git-scm.com/docs/index-format). Split-index metadata is captured and parsed through a controlled shadow. No Git command reads the held repository configuration, hooks or filters. External gitlinks, missing objects and unparsed operation state such as index locks or rebase/fetch receipts remain explicit recovery obligations. The original bytes are still archived.

Before any future registration removal, a separate handoff must durably preserve the transitive object closure for all dependency endpoints and account for every unparsed or external dependency. This module always reports `durable_handoff_verified=false` and `registration_removal_authorized=false`.

`validate_capture(view, artifact_path, scratch_directory, binary)` is available to a caller already holding the frozen view. The caller must first establish private directory and trusted runtime authority, as the shared shadow helper does. Validation compares the complete artifact with the current frozen source and recomputes the dependency set. A caller cannot gain acceptance by deleting inconvenient object IDs from a receipt. Validation does not acquire a second gate lock or grant deletion authority.

The tiny real-Git tests cover dirty/staged/untracked data, split indexes, binary xattrs, symlinks, cache-tagged unique bytes, source/archive corruption, omitted dependency IDs, nested registrations, wrong approval, same-boot refusal and low-disk refusal. They simulate the gate's later boot in disposable directories. Actual privileged legacy gate and reboot acceptance remain separate requirements.
