# Failed managed workspace creation

`managed-workspace-failed-creation.py` recovers private image storage that never reached an initialized provider or published manager lifecycle. It is an internal service module, with no arbitrary-path cleanup CLI. The caller holds the permanent creation request lock. The module verifies the exact durable request and takes the provider UUID lock.

`recover_failed_creation(provider, request, authorization=...)` accepts an exact owner cancellation (`kind: owner-cancel`, matching `session_id`) or a verified different machine boot (`kind: new-boot`). The broker must authenticate the owner before supplying cancellation. A speculative same-boot or unknown-boot sweep returns a blocked result without creating cancellation intent. Explicit cancellation publishes `failed-creation.json` before attempting recovery. Every existing failed-creation journal permanently vetoes reactivation of that UUID.

Published or initialized workspaces use the normal terminal lifecycle instead. An attached unpublished image must detach normally and disappear from the validated attachment inventory. Busy mounts remain intact. An interrupted detach whose image is already absent cannot become a successful receipt on retry in the same boot. A valid different kernel boot or an already complete provider detachment record is required. Empty or missing boot information is not an absence proof.

After cutoff, the module pins the private sparsebundle and captures all regular files, their bytes and ownership, mode, timestamp and outer extended-attribute metadata in a compressed raw archive. It does not need a valid filesystem or Git repository inside the image. Unsupported links, special files, external filesystems and externally hardlinked files are retained as explicit failures. Outer extended-attribute bytes are preserved in the manifest and each entry’s `RICHOS.xattrs` PAX field; unreadable attribute metadata blocks recovery. The archive is read back entry by entry and hashed. The source is compared again before durable reclamation intent. Only then can that exact sparsebundle be removed. Interrupted band removal resumes against the verified archive and pinned directory identity. A replaced source, changed archive or unknown attachment inventory stops recovery.

The separate journal exposes `creation-blocked`, `creation-reclaiming`, `creation-retained` or `creation-empty` through `inspect_failed_creation`. Raw archives have no automatic expiry: the incomplete image can contain unique work that cannot be classified safely. Compression and removal of the original sparsebundle can reclaim disk space, but the module does not promise that every raw archive compresses well. An owner-cancelled request whose provider never reserved its UUID can receive an atomic empty receipt after strict image absence. Publication uses exclusive rename and never replaces an unexpected path. This relies on holding the permanent request lock and the provider invariant that it reserves the UUID before launching hdiutil and never deletes that directory. A speculative new-boot check cannot infer an empty reservation without prior evidence. Empty reservations make no reclaimed-byte claim.

The tests use real private files, compression, archive verification and interrupted deletion. Only attachment and boot observations are substituted. They establish source-level recovery behavior, not an installed root/user privilege boundary. Installed macOS acceptance remains separate. Neither these tests nor this module install or activate a service, change canonical repositories or clean up a live workspace.
