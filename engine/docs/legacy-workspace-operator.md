# Explicit operator maintenance authorization

Legacy Codex worktrees and canonical checkouts may have no Claude terminal history. An operator can authorize their exact maintenance scope without inventing agent records. This authority is separate from evidence that any process has stopped. Known live worker evidence still blocks staging. The existing whole-repository gate and actual later-boot cutoff remain mandatory before capture and retirement.

The installed root administrator first produces a normal owner report using `legacy-workspace-admin.py plan`, explicit repository aliases, the owner UID and the exact transaction/ledger paths. A complete decision list assigns `remove` or `retain` to every logical gate target. Each decision binds the alias, path, filesystem identity, Git administration path and observed HEAD. `legacy-workspace-operator.decision_record` constructs this reviewable record from a report target. Canonical checkouts and shared Git stores always require `retain`. Retaining an old terminal worktree also removes it from the job's selectable retirement candidates.

The explicit `attest-maintenance` operation takes the original `--report`, its `--approved-sha256`, a `--decisions` JSON file and `--authorization` text recording the user's maintenance instruction. It regenerates the complete report as the approved unprivileged owner before any authorization file is written. Changed HEADs, paths, administration, history or shared-parent scope refuse the old approval. The immutable root-owned mode-0600 document is stored under the configured private root's `legacy-authorizations/<UUID>.json`.

The result contains an `operator_attestation` descriptor and a new report. The descriptor's path and canonical JSON SHA-256 must accompany `plan`, `stage` and subsequent gate commands through `--operator-attestation` and `--operator-attestation-sha256`. Stage still requires the exact new report and its approved hash. Gate and job creation remain separate operations; attestation itself neither stages repositories nor activates a service.

Before the privileged controller forwards an attestation to the owner inspection helper, it verifies the fixed protected namespace, file owner/mode, hash and owner UID/GID. The owner helper independently regenerates the original report and applies only the exact approved decisions. It preserves original history and ownership evidence, explicitly records every waived blocker and labels operator-selected candidates without synthetic session IDs or terminal events.

Only exact `unknown-owner` and `registration-recovery-needs-exact-terminal-owner` blockers can be covered by this authorization. Live-owner evidence, incomplete or malformed history, unsafe storage dependencies, symlinks, identity mismatches and other inventory errors remain blockers. A new or changed namespace requires a new report and explicit authorization; an old attestation cannot be broadened after staging.

Directory retirement and branch retirement are independent selections. Preserve unmerged ordinary branches. The ordinary capture and Git object-recovery checks preserve unique working, staged and committed data before any selected directory disappears. Attestation grants no direct delete, prune, force-unmount or reboot operation.
