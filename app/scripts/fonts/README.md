# Vendored typefaces

Everything RichOS renders text with is in `app/ui/fonts/`. Nothing there is
fetched at runtime and nothing there is provided by the operating system:
`tauri-codegen` brotli-compresses every file under the staged frontend into the
executable, so these faces are part of the binary, hashed into its signature and
present before the first frame.

That is the whole point of the directory. `wiki/ceo-decisions.md` §22:

> For obvious reasons, there cannot be any reliance on any system fonts when
> implemented in the RichOS app later.

**The two faces are the CEO's, decided 2026-09-01: "Typeface: GO."** Serif is
**Newsreader**, sans is **Inter**, both SIL Open Font License 1.1. There is no
third role — see "The monospace hole" below, which is an open question and not
an omission.

`app/ui/fonts/fonts.css` is the only file in the product that names a typeface.
`style.css` composes those names into `--font`, `--font-serif` and `--mono` once;
every rule in the app says `var(--font)` or `var(--mono)`.

The four `LICENSE-*.txt` files add 17,537 bytes, and they ship too — the OFL
requires the license to travel with the font, and these are embedded in the
binary exactly as the fonts are.

**Total added: 317,285 bytes.** Against the 8.8 MB payload ruled in §19 that is
**+3.5%**, and it is measured rather than estimated: the byte counts above are
`stat` output on the files in that directory.

Every figure here can be regenerated by `./rebuild.sh`, which prints the same
table. A record that disagrees with the directory it describes is worse than
none.

## Why Inter is cut wider than the approved mockup's copy

The approved `round-11.1/v1` mockup vendors Inter as **two static instances,
400 and 500**, subset to Google's `latin` range. That is right for one screen and
wrong for this app, and the difference was measured rather than argued:

* **Weights.** The app sets 21 rules at 600 and one at 700. Neither is in those
  two files, so both would be synthetically emboldened — a fake bold of a face
  that has a real one.
* **Characters.** The start screen renders 5 non-ASCII characters. The app
  renders 30. Google's `latin` subset carries 9 of them; the other 21 would fall
  through to a system font.

Same face, same upstream, same license — a wider cut of it, clipped on the weight
axis to exactly what the app uses so it still costs less than the full variable
file (122 KB against 168 KB).

**Newsreader is NOT re-cut.** Its two files are copied byte-for-byte from the
approved mockup and their sha256 matches what that round's README records.
Rebuilding an approved artifact to no benefit is how a second, unreviewed version
of an approved thing gets into a repository. `rebuild.sh` verifies them and
refuses on a mismatch rather than regenerating them.

Newsreader is vendored but **not yet used**: no text in the app is set in a serif
today. It is here so the start screen's type arrives with the screen rather than
after it, and so `--font-serif` is real the moment a designer reaches for it.

## The seven glyphs neither face carries

The interface draws its own controls out of Unicode — the settings gear is a
literal `⚙` in `index.html`, the navigation toggle is `☰`, every close button is
`✕`, the voice control is `◉`, the working state is `◐`.

Measured against each face's own character map: of the 30 non-ASCII characters
the shipped UI renders, **Inter carries 23 and Newsreader carries 9, all nine of
them inside Inter's**. Seven are in neither — `⋯ ▾ ◉ ◐ ☰ ⚙ ✕`.

A browser that cannot find a character in the named family walks silently to the
next one, so with only the two approved faces vendored, a system font draws the
gear, the hamburger and every close button — the ruling broken in the most
visible place there is. Three Noto subsets close it for **3,080 bytes**, each cut
to exactly the codepoints it answers for and declared with a `unicode-range` so
the browser never consults it for anything else.

**Whether to keep them is the CEO's call**, and it is open. They set no text and hold no role in the type system, so they are
glyph coverage rather than a third family — but the cleaner long-term answer may
be to stop drawing controls with text characters at all.

## The monospace hole

Ten rules use `--mono`: the memory location, the desk record and its suppressed
id, the feedback entry key, the technical view's title, path and raw output, the
techy reason, and the update detail. All are technical text where column
alignment is the point.

There is no monospace in the approved pair, and choosing one was ruled to be the
CEO's decision. So `--mono` resolves to the **generic `monospace` keyword** — the
browser's own last resort, which the ruling permits, rather than a named platform
face, which it does not.

**Be clear about what that costs**: the generic keyword resolves to whatever
monospace the machine has, so those ten rules still look different on a different
computer. They are diagnostic surfaces rather than the product's voice, which is
why this is a tolerable place to stop — but it is stopping, not finishing.
That decision is open and has not been put to him.

## Coverage limits, stated rather than discovered later

Inter is subset to Latin-1, Latin Extended-A, the combining marks, and the
punctuation/currency/arrow/math/symbol blocks an English-language interface uses.
Western European text is complete. **Latin Extended-B, the IPA extensions, Latin
Extended Additional (Vietnamese), and every non-Latin script are not carried** —
Inter has no CJK at all, so no subsetting choice could have covered that.
Newsreader carries Google's `latin` range and nothing beyond it.

Text outside those ranges falls to the generic `sans-serif` / `serif` /
`monospace` keyword, which is the browser's own last resort and the one thing the
ruling leaves permitted, so that text is never invisible.

Adding a range costs bytes and nothing else: change `TEXT` in `rebuild.sh` and
re-run it.

## Licensing

All four projects are **SIL Open Font License 1.1**, confirmed by reading each
project's own license file rather than a summary of it, and each of those files
is committed beside the fonts:

| Face | Copyright statement, verbatim from its license file | File |
|---|---|---|
| Inter | `Copyright (c) 2016 The Inter Project Authors (https://github.com/rsms/inter)` | `LICENSE-Inter.txt` |
| Newsreader | `Copyright 2020 The Newsreader Project Authors (http://github.com/productiontype/Newsreader)` | `LICENSE-Newsreader.txt` |
| Noto Sans Symbols, Noto Sans Symbols 2 | `Copyright 2022 The Noto Project Authors (https://github.com/notofonts/symbols)` | `LICENSE-NotoSansSymbols.txt` |
| Noto Sans Math | `Copyright 2022 The Noto Project Authors (https://github.com/notofonts/math)` | `LICENSE-NotoSansMath.txt` |

**None of the four declares a Reserved Font Name** in its copyright statement,
which is what makes the subsetting here permitted — OFL §3 restricts only names
reserved that way, and no copyright line above carries the "with Reserved Font
Name" clause. The families are declared under their own names in `fonts.css`, so
nothing is passed off as something it is not.

Three faces are deliberately absent and should stay absent. They are named in
`wiki/ceo-decisions.md` §22 and deliberately **not** named here:

* the commercial face the wordmark was drawn with — never authorized, and not
  needed, because the wordmark ships as outlines;
* the two Apple-supplied serif faces the early mockups were set in — the mockups
  may use them, the app cannot, for exactly the same reason it cannot use the
  platform interface faces.

Writing them out here would put the names back in the tree for the next person to
find and ask about, which is the conversation this whole change exists to end.
§22 is one click away and is the authority; this file does not need to be a
second copy of it.

## Rebuilding

`./rebuild.sh` verifies the two approved Newsreader files against their recorded
hashes, downloads the four upstream archives, verifies those against the hashes
above, and regenerates the five subset `.woff2` files. It needs `python3` and the
network, and it builds its own throwaway virtual environment for `fonttools` —
nothing is added to the repository's dependencies.

## Adopting a different face

1. drop the `.woff2` and its license file into `app/ui/fonts/`;
2. change the `src:` line in the matching `@font-face` block in `fonts.css`;
3. change the family name in `--font` (or `--font-serif`) in `style.css`, if it
   differs.

Nothing else in the app names a face, so nothing else has to move.
