# What of the CEO's this branch changed: five files untouched, one I have to report

Both verification directories on this branch claim the CEO's state is byte-identical, and at
the moment each of them was captured that was true and sha256-verified. A final sweep at the
end of the session found one file that no longer matches its start-of-session baseline, and
this file exists so that fact is not left sitting inside a superseded log.

## The measurement

Start of session and end of session, sha256 over every file under
`~/Library/Application Support/com.richos.app`:

```
five of six  byte-identical
             config.json, conversation-ledger.jsonl, navigation.json,

launches.json  db78c9f98c33801b…  ->  af4b7bbf6b69fe39…
```

Everything else is untouched and re-verified at the end: the pointer
`~/Library/Application Support/RichOS/loro-root` still resolves to `/Users/alex/ab/richos-hq`,
`~/ab/richos-hq` is clean, `~/.claude/richos-engine` still resolves to
`/Users/alex/ab/richos/engine`, and `pgrep -f richos-tauri` returns 0.

## What the changed file says

```json
{"schema_version": 1, "installed_at": 1788211347666, "starts": [1788211347666],
 "recent_splashes": [], "rewards_fired": {},
 "open_run": {"started_at": 1788288588015, "token": "23165"}}
```

`open_run` is `launch.rs`'s marker for *a run that began and was never marked as having
exited cleanly*. `started_at` is **2026-09-01 19:49:48** local; `token` is the process id.
No process with that id is alive and no `richos-tauri` is running, so a launch of the
installed app began at 19:49:48 and ended without closing its own record.

## Whether it was mine

I cannot prove a negative about someone else's launch, so here is what I measured rather than
what I believe.

**Every launch this branch's harness makes is given a scratch `$HOME` under `mktemp -d`.**
`gui_boot` passes `HOME="$home"` where `$home` is the machine directory, and Tauri's
`app_data_dir()` follows `$HOME` — demonstrated by every scratch machine carrying its own
`Library/Application Support/com.richos.app`. There is no code path in the harness that
passes the operator's `$HOME` to the binary.

**I then tested it rather than asserting it.** Each of the six `app/scripts/*.test.sh` suites
was run individually with a sha256 of `launches.json` taken immediately before and after:

```
unchanged  frontend-payload.test.sh
unchanged  gui-boot.test.sh
unchanged  package-app.test.sh
unchanged  rebuild-survival.test.sh
unchanged  signing-setup.test.sh
unchanged  updater-setup.test.sh
```

The 19:49 timestamp also falls after my last clean sweep of the same six files, which was
identical, and the only things I ran between those two points were `run-tests.sh` (the six
above) and `app/ui/tests` — which drives WebKit against `file://` pages and never starts the
Tauri binary at all.

The most likely explanation is a human or another agent launching the installed app around
that time; a typography change landed on `main` in the same window and is exactly the kind of
change somebody opens the app to look at. **That is a hypothesis and it is named as one.**

## Why I did not put it back

I have the original's sha256 and not its bytes. Two reconstructions —
`"open_run": null` with and without a trailing newline — hash to `e145ee4f48fd0a0b20b4…` and
`9bd40fe01144c1829983…`, and the original is `db78c9f98c33801b918e…`. Neither matches, so
restoring it would mean writing a guess at the CEO's data into the CEO's data. **A guessed
restoration is worse than a reported change**, so the file is left exactly as found and this
note exists instead.

## What it costs him

One splash, once. `launch.rs` reads an unclosed `open_run` as a crash-restart, so his next
launch is not counted as a fresh start, the opening screen is skipped, and he lands back
where he was. The record itself is intact, nothing is lost, and the next clean exit clears
the marker.
