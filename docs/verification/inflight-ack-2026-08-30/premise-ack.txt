WHAT THIS CHANGES, AND WHAT IT DOES NOT:

  The instruction's conclusion stands, on the surviving ground. A reply the
  lead may never receive proves nothing to the lead, whether or not the tool
  exists. So the ack stays a durable artifact the lead can stat, and the
  spawn-time contract stays a spawn-time contract.

  What changes is that the witnessed reply is not dead. worker-events.jsonl
  is written inside the SENDER's execution at the moment its tool call
  resolves, so it records the send even when delivery drops. That makes it a
  real durable substrate, not a mailbox read — and it is therefore accepted as
  a SECONDARY ack channel, never the primary one, because it carries only the
  200-character `summary` field and so cannot carry a restatement.

This file is itself the first working instance of the mechanism: an
acknowledgement that exists as a committed artifact rather than as a message,
and can be verified by anyone with a filesystem.
