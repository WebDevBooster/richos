MUTATION RUNS — app/scripts signing suites, 2026-08-31
======================================================

56 checks across three suites. 54 of them were turned RED at least once by
breaking the SHIPPED SOURCE and re-running; the two that were not are named at
the foot of this file with the reason, rather than left for a reader to notice.

Why this file exists, in this project's own words: an exit code is not evidence.
A check that cannot fail proves nothing, and the failure it hides is invisible
precisely because everything is green. Eight silent mutations across three
branches on 2026-08-30 each meant a check was not running.

METHOD. Commit first, mutate second, restore with `git checkout --` from the
commit. Each mutation is a single replacement in the shipped script — never in a
test — chosen to be the plausible regression rather than a deletion of the whole
function. The suite is then run in full, so a mutation that reddens the WRONG
check is visible.

Base commits: 46820bf (the two setup scripts), e7eccf4 (package-app.sh).

nothing.

THE TWO CHECKS WITH NO MUTATION, and why
--------------------------------------------------------------------------
package-app.test.sh  Z   the operator's real keychain inventory is unchanged
signing-setup.test.sh Z  the operator's real keychain inventory is unchanged

Both are negative controls on the SUITE, not on any shipped script: they snapshot
`security find-identity -v -p codesigning` before the first case and compare after
the last. There is no edit to package-app.sh or install-signing-cert.sh that can
turn them red, because nothing those scripts do in these suites reaches the real
keychain — which is the property being asserted. Turning them red requires
mutating the suite (removing the `--keychain` sandboxing or the shim), and this
record does not count a test-mutation as evidence about shipped source.

They stay because the failure they guard against has happened in this project's
own history: `engine/scripts/locate-engine.test.sh` carries the same check for the
same reason, after an installer repointed the live operator pointer at a temp
directory that was deleted seconds later.

--------------------------------------------------------------------------
WHAT NONE OF THIS PROVES
--------------------------------------------------------------------------
No Developer ID certificate exists on this machine or any machine in this
project — `security find-identity -v -p codesigning` reports 0 valid identities,
measured again 2026-08-31. So nothing here has ever been signed with a real
identity, notarized, or stapled. The cases marked [shim] prove what the SCRIPTS
do with an identity inventory and with credentials; they prove nothing about
codesign, notarytool or Apple.

And package-app.sh cannot build a bundle on this tree at all: the icon gate
refuses on the placeholder icon set (CEO item 2.6, the artwork, still open). The
bundles in section D and in the rebuild-survival suite are minimal .apps built by
hand and ad-hoc signed by the real codesign, which is what makes the verification
arm exercisable at all.
