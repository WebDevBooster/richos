This is NOT a unit test. It is one real turn, through the real adapter, with real tool
calls, landing real bytes in the real journal on disk. What it establishes:

  * Section 1 — the CEO's conversation contains ZERO machinery. Same as before this work.
  * Section 2 — text and machinery share ONE per-turn counter (§1.4 G1). The CEO's turn
    reports "35 items, positions 0..=34, unique: YES, dense: YES": every position used
    exactly once, no gaps, across BOTH families. That is the reconstruction two
    independent counters cannot express.
  * Section 2 — the re-prime turn's 4 records carry turnId None and internal: true (§1.5),
    and report dense: NO because the positions missing from them are the priming TEXT,
    which is discarded unrendered. The gap is the proof it was there and deliberately not
    kept.
  * Section 3 — 24 journal lines project to 9 rows: three tool calls, each merged from
    5-7 wire events by toolCallId (§1.4 G2/G6), each with the REAL title rather than the
    "Terminal" / "Read File" placeholder the open event carried, each ending "completed",
    each with a bounded summary and (for the Read) its file path. Plus one
    permission_requested recorded as an observation — "auto-approved: allow", no control
    attached — and five usage_update records retained as `unknown` because usage is
    Phase 2 and a Phase-2 kind must still not be dropped.
  * Section 4 — the day shard is a PAIR of files: 2026-08-28.jsonl (Tier A, ~10 KB,
    never evicted) and 2026-08-28.raw.jsonl (Tier B, ~32 KB, unlink-evictable), 24 lines
    each.

Note on the one absence: session_info_update does NOT appear. It arrives AFTER the prompt
response, when current_prompt is already None, so it reaches no sink — the between-turn
route is §1.5's design and §5's PHASE 2. Named as a known hole, not a silent one.
