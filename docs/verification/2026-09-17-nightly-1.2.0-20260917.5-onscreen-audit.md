## One observation I am recording but NOT calling a defect

**The app is running and reports zero windows, and its own boot log says it found no display.**

*Basis: read from the running app's log and from the accessibility tree. NOT verified on screen —
the screen is dark, which is the whole point.*

```
[richos] window: the runtime reported no attached display
[richos] window: fallback 1024x700 pt centered by the platform, min 1024x700 — no display could
   be read; the smallest size the UI is designed for is the last resort and the platform is left
   to center it
```

against candidate .4's log at the same launch path, with the screen awake:

```
[richos] window: restored 1024x700 pt at (664,108), min 1024x700 — where it was left, still
   inside Monitor #30942 work area 1920x1005 pt at (0,25), scale 1
```

Two things about this are worth someone's attention, and **neither is established**:

1. **macOS still reports all three displays `Online: Yes`** while they sleep — asleep is not
   detached. If the app is treating "asleep" as "no display attached", that is a wrong reading of
   the machine, and it decides where the window goes. It may equally be that the runtime genuinely
   returns nothing while the display is asleep, in which case the app is reporting what it was
   told and there is no bug here at all. I cannot tell these apart from outside.
2. **There is no window now.** `System Events` returns `0` windows for `richos-tauri`. That is
   consistent with a window that was never created, and equally consistent with an accessibility
   tree that does not expose windows for a binary at a path that has not been granted anything —
   this bundle sits at a **new path** from candidate .4's, and audit-4's window queries worked
   against the old one. A clean `0` rather than an error does not settle it.

**What would settle both:** one relaunch, or one re-front, with the screen awake — the same
conditions audit-4 ran under. If the window comes back at (664,108) on a monitor the log names,
this was the sleeping screen and nothing more.

**Why I am not ranking it:** a person is not sitting in front of a dark screen wondering where his
window went. Whether this can happen to the CEO in a way he would feel — the displays sleeping
under a running RichOS and the window not coming back when he wakes them — is a real question, and
it is a question, not a finding.
