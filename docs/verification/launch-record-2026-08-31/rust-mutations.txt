HOW TO READ THIS FILE
  RED: <names>     the mutation was applied, the gate ran, and exactly these turned red.
  NOTHING TURNED RED   the mutation changed shipping behaviour and every check stayed
                       green. That is not a spare check — it is a check that CANNOT FAIL,
                       and each one below was chased down. Three were found on this branch
                       and all three were real:

    M4  / M4b  the offset was replaced in ONE of five places in `LaunchCounts::of`, so the
               remaining four still applied it and nothing moved. The MUTATION was too
               weak, not the check. Re-run replacing it everywhere: RED, five checks.
    M5  / M5c  DELETING the week walk-back entirely left everything green, because every
               reading in the test was anchored on a Monday — the day on which the
               walk-back has nothing to do. A REAL HOLE. The test now also reads mid-week,
               on the Thursday, and the same mutation is RED. Fixed in commit 36e4942.
    M32        removing `utc_offset_minutes` from `launch_state`'s SIGNATURE and
               re-declaring it as a local inside the body left everything green: the check
               matched the token anywhere in the extracted function text, and that text
               includes the signature. A REAL HOLE — the webview's offset would have
               stopped reaching the record and every bucket would silently have become UTC.
               The check now reads the signature and separately refuses the shadowing
               `let`. Re-run: RED.

  did not compile   the mutation was rejected by the compiler rather than by a check. Named
                    honestly and NOT counted as evidence: a build failure proves the type
                    system objected, which is not the same as the check objecting. M9 (a
                    stored counter added to the record) and M27 (a defaulted schema version)
                    are both in this class; `there_is_no_stored_counter_anywhere_in_the_record`
                    and the two version tests earn their keep through M17/M18/M26 instead.

  Ids with a letter suffix (M4b, M5c) are re-runs of the id above them, after the cause of a
  silent pass was fixed. Both the original and the re-run are kept: deleting the silent one
  would delete the finding.
