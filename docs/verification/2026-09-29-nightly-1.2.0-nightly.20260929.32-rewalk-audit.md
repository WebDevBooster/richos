## Item 2 — why the updater change cannot be seen before publication

The change is in `spawn_past_lock_steps`, which `probe()` uses. `probe()` runs when the RUNNING
app stages an update or a rollback (`stage_verified`, `stage_rollback_verified`, `recover`). So
.32's own copy runs only when .32 stages something: a newer nightly, or the way back to `.29`.
The way back needs `.32` to have been installed BY the updater, from a manifest under
`/releases/download/v1.2.0-nightly.20260929.32/`, and a release build refuses a non-https
endpoint (`scripts/updater-e2e.sh` header). That manifest does not exist until Rich publishes.
When the CEO updates `.29 → .32`, it is `.29`'s code that stages the update.

So the on-screen proof is the first rollback, or the first update after this one, taken from
`.32`. The commit's own assessment: *"No path was found where the shipped app refuses its own
update."* The gate evidence above is the proof available today.
