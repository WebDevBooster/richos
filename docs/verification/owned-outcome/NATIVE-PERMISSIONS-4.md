# Native permission recovery in R4

The first R4 native trial parked at a permission dialog for a routine shell-based file read. The native policy now denies the first operation attempt with recovery instructions. This returns control to Claude, including native children, so it can use an existing permitted alternative. No permission is granted. Explicit `deny` policy remains deny-only.

A repeat with actual necessity evidence can invoke the separate tool-free Sonnet necessity reviewer. Ordinary repeated shell preferences without evidence do not invoke it. The reviewer must cite verified human scope and either a literal exact-operation requirement or actual distinct failed alternatives from that same native actor. It sees observed configured permissions and adapter recovery denials as data. Those denials are not CEO prohibitions. Inspector output never becomes worker policy prose. The host returns only a source-bound descriptor and recovery or native-prompt disposition. A native prompt still needs the native user's actual permission choice.

The host keeps first-attempt counts per operation and source revision, because Claude retries with a new tool-use ID. Prompt exposure and review reservations are instead bound to the actual native invocation. Claude's PermissionRequest payload in the observed runtime omits tool_use_id. The synchronous PreToolUse observer retains the runtime tool_use_id before transcript flush, without inference or any CEO authority from its input. The host resolves it from those observed IDs and the saved leader transcript or that leader's native child directory. Actual native results reconcile completed observations. This observation was added after the second real trial proved that the transcript can still omit the current tool call when PermissionRequest fires. It selects a unique outstanding same-tool call, preferring exact input. A unique same-name fallback supports another hook's input rewrite. The latest native assistant requestId group separates a resumed model turn from abandoned earlier calls. Ambiguous or absent binding cannot expose a permission prompt.

Before inference, the host reserves that operation's review under a lock. It checks the reservation, invocation and current source again before exposing native UI. A new UserPromptSubmit payload cannot grant authority, but its prompt_id fences old authority until the corresponding native promptId row is flushed. This also fences cached Agent registration and dispatch. Positive typed-human provenance establishes authority; an observed matching machine row resolves the temporary fence without becoming human authority. A source that never becomes corroborated remains an integration recovery condition.

An exposed prompt is not a permanent ban on the operation. A successful actual tool result allows a distinct future invocation to receive a fresh necessity review. It does not reuse the prior permission grant. Native toolDenialKind=user-rejected is positive refusal evidence. Reconsideration requires a later verified human source interpreted in the context of the previous operation. The user can say “go ahead with that operation”; they do not have to retype its command. An unrelated new message does not semantically reconsider the refusal. The host requires the reviewer to cite that later source separately from the original necessity evidence.

Generic tool errors and missing results are not inferred refusals or approvals. An unknown prior prompt requires a later successful same-actor Read, Glob or Grep receipt and a necessity review that assesses the actual effects before a new invocation may expose UI. An unrelated read is not sufficient semantic evidence. Crashed review reservations expire so recovery is possible. Provider failure is recorded privately, returns recovery and paces retries without granting anything.

Focused deterministic coverage includes pending cancellation during registration and permission review, cache preservation, concurrent reservation, child source binding, a new invocation after successful execution, positive native refusal, contextual reconsideration, generic errors and a crashed prompt with no result. These tests establish host behavior and protocol boundaries. The separate live trial records determine whether native Claude actually recovers and finishes the assignment without user intervention.

The trust boundary remains native runtime metadata and local host storage. This does not protect against a process capable of rewriting its own native transcripts or host ledgers. Unknown provenance is never silently upgraded. Historical R3 reports retain their original passthrough-policy description because those were the bytes tested then.

The exact-operation trial exposed an existing native hook adding `set -e -o pipefail` plus a newline before the requested command. Necessity now relates the original observed PreToolUse input to the full effective PermissionRequest input by matching the same actor and tool-use ID. Only an unchanged command or that fixed observed safety prefix qualifies, with every other field equal except the cosmetic description. Added or changed execution flags, additional commands, other wrappers, unmatched IDs and caller-supplied original claims do not. The effective input remains complete in the prompt ticket and native UI. The same relation prevents a wrapped copy of the same failed call from being counted as a distinct alternative.

Live permission-boundary scoring records terminal chunk timestamps and offsets. Native can render its permission dialog while the PermissionRequest hook is still running. The final exact-operation trial demonstrated this timing: its current required-command UI appeared after the exact PreToolUse observation and remained unchanged when the host completed necessity validation. The meter accepts either UI received after the callback or an unchanged frame drawn during that exact invocation, bound to the completed host prompt ticket and original/effective inputs. Historical setup/trust UI, unmatched invocation IDs and a different command cannot satisfy the check. The original after-return-only meter failure remains preserved alongside the corrected evaluation of the same trial. No additional provider run was used to correct that measurement.

Native UI limit: the same trial also captured a transient routine compound-read permission dialog before automatic recovery denied that attempt. Claude draws this UI before the hook has returned. Work continued without an answer. This integration does not promise that a native permission dialog can never flash; it preserves required permission boundaries and recovers routine requests without an operational answer or lasting stop.
