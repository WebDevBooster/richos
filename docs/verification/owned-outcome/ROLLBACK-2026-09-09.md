# Orchestration rollback, September 9, 2026

The CEO requested removal of the integration after repeated dispatch and stop-hook
failures. This rollback removes it instead of adding another recovery mechanism.
It does not claim that unattended orchestration is implemented.

## Repository changes

Work was isolated on `codex/rollback-owned-outcome` in a separate worktree. The
first commit, `984f72e9`, made the two native hook entry points inert immediately.
The subsequent code reversal removes:

- The managed assignment controller, registrar, worker and inspector modules,
  terminal runner, desktop commands and assignment panel.
- Native owned-outcome hooks, policy redirects, installer and their dedicated
  tests and provider-trial scripts.
- Runtime doctrine additions that promised the removed execution team.

This is a selective inverse, not a reset of main. The original durable feature
is reversed against merge `727d8890`'s first parent. The owned-outcome code changes
are reversed from `b80f9978`, `2b9d7122`, `5f519822`, `e0679a55`, `d8afbc1f`,
`125906f5`, `0c0d2b43`, `9e3d2edb` and `ed88e290`. The dependent dispatch repairs
`7d77e3bd` and `0e865973` disappear with the dispatch implementation.

Later unrelated work remains, including company onboarding, its scoped MCP tools,
chat doctrine and skills delivery, conversation cancellation and crash recovery,
voice, application updates and the existing engine guards. Shared-file conflicts
were resolved to preserve those changes. A small conversation-lease clearing
helper and primed-thread identity remain because subsequent ordinary conversation
recovery and onboarding depend on them. They launch no worker or inspector.

One pre-existing rotation test had adopted the removed worker-only prompt API.
It now exercises ordinary conversation recovery and verifies that the failed
rotation record survives a successful retry. Its previous expectation that an
error must escape the call no longer applies to the retained conversation path.

## Cached-hook compatibility

`engine/scripts/lib/owned-session.py` and `owned-dispatch.py` intentionally remain
as tiny inert files. Already-running Claude Code sessions can cache their hook
commands until restart. Deleting the paths immediately would replace the broken
integration with missing-file hook errors. The shims read no input, write no
state, start no process and exit zero. They contain no integration logic.

Historical reviews, signoffs and evidence remain in Git. Active README and event
contract claims were updated; the old feature guides are labeled historical.
Keeping the audit history does not keep the feature installed.

## Validation

No model calls or paid provider trials were needed for removal.

- `cargo test --manifest-path app/Cargo.toml -p richos-core`: 980 ordinary tests
  passed, 4 explicitly ignored tests were not run and 5 doc tests passed.
- `cargo check --manifest-path app/src-tauri/Cargo.toml`: passed. Two existing
  unused-constant warnings in `activation.rs` remain.
- Real WebKit steering suite: passed, including Stop, thread-scoped cancellation,
  three viewport sizes and no browser page errors.
- Real WebKit onboarding lifecycle suite: passed, including acceptance, decline,
  company switches and stale responses.
- Six documentation-to-source checks passed. Changed JavaScript and shell scripts
  passed syntax checks. Both compatibility entry points exited zero quietly.
- `git diff --check`: passed.

Initial WebKit invocations could not locate Playwright in the fresh worktree.
They were rerun successfully using the existing installation through the harness's
`RICHOS_PLAYWRIGHT` setting. No dependency installation was performed. Initial
rollback test failures exposed a remaining reference to the removed worker API
and a doctrine assertion mismatch; those were corrected before the passing full
core run. Neither initial attempt was counted as a pass.

Local validation logs are in the private artifact directory
`~/.codex/artifacts/owned-outcome-rollback-20260909/`, named
`repository-{core,app-check,steering,onboarding,docs}.log`.

## Machine installation

The coordinating rollback also removes the owned hook registrations and ignored
configuration from all three adopter repositories, removes the versioned owned
runner installations and retires only the integration's state into private
rollback backups. The shared engine pointer remains because unrelated existing
guards use it. The final installation receipt is appended after integration.
