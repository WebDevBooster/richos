### The root cause is bigger than the job, and it would hit a real user on update

The engine directory that broke candidate .7 **and** candidate .8 was **yesterday's engine**, still
sitting in place under today's version number. The app compares version *strings*, so it never
noticed.

I verified this three independent ways (§3). The short form: the app **records the digest of the
engine it installed** and **pins the digest of the engine it wants**, and **compares neither** — it
compares `1.2.0` to `1.2.0`. Two different engine tarballs, one version string, silently accepted.
That is the freshness contract's own failure mode — *identity or refuse* — in the product. **Any
user who updates RichOS while the engine version string is unchanged keeps the old engine forever,
and every background job then fails with an engineer's sentence.**

## 3. The engine swap, mid-walk — recorded as Rich stated it, and then checked

**Rich's message, and this is his account:** the app resolves its engine directory **by VERSION pin
only** (`engine.rs resolve_engine_dir_pinned`); the scratch HOME carried an engine directory copied
forward from candidate .7's HOME that **predates the seat feature** (no `seat_of` in its
`ecs/adapters/app.py`); same version string, different content. He quit pid `76497` at ~`10:39:13Z`,
replaced that directory with the engine tree at `b0063d98` (`git archive`), relaunched, found the
first relaunch rejected it for having **no delivered runtimes**, restored the untracked
`runtime/`, `LICENSE`, `THIRD-PARTY-NOTICES.md` and `INSTALLED-FROM` from the old copy, and
relaunched again as pid `85513` at `10:40:48Z`. He kept the old copy at
`scratchpad/richos-qa-cand8/engine-stale-103900`.

**I re-derived every load-bearing part of that, and it holds — and it is worse than he put it.**

**(a) The resolver compares the VERSION string and nothing else.**
`richos/app/crates/richos-core/src/setup.rs:244`:

```rust
pub fn engine_accepted(dir: &Path, needed: Option<&str>) -> Result<(), EngineRejected> {
    if !engine_looks_valid(dir) { return Err(EngineRejected::NotEngineShaped); }
    let Some(needed) = needed else { return Ok(()) };
    let found = engine_version(dir);
    match found.as_deref() {
        Some(v) if v == needed => Ok(()),
        _ => Err(EngineRejected::WrongRelease { found, needed: needed.to_string() }),
    }
}
```

`engine.rs:228 accepts` delegates straight to it, and `resolve_engine_dir_pinned` calls `accepts`
for every candidate. There is no content check anywhere in that path.

**(b) The stale directory really was yesterday's, and really did predate the feature.**
