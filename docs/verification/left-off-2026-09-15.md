## 1. One premise in the brief did not survive, and it is the acceptance number

**The brief's acceptance test:** replay the session at 06:41 and show that the output would have
answered *"TLDR, plain English"* correctly and immediately — **"the CI burn going 46% to 22%"**.

**22% cannot be produced at 06:41, and reproducing it would require the replay to see the
future.** Raised as `esc-20260915T091730Z-ad7611e3` (state: proceeding) before any of this was
built. Re-derivable in full at `left-off-2026-09-15/raw/two-windows.txt`:

```
  finished 2026-09-14T21:45:16Z  dispatched 2026-09-14T21:25:58Z    218,627  zach-opus-silent1      Why was the blocking guard silent
  finished 2026-09-14T22:29:15Z  dispatched 2026-09-14T21:30:53Z    275,567  sage-opus-vdesign1     Design the verification layer
  finished 2026-09-15T06:57:38Z  dispatched 2026-09-15T06:43:17Z    139,931  tom-opus-r9fix1        Fix the cross-repo test fixture

WINDOW A -- 21:39:46Z (his last message) -> 06:41:29Z (his return)
  2 job(s), 494,194 tokens
WINDOW B -- the same start, NO END, evaluated at 07:11:37Z when the command was run
  3 job(s), 634,125 tokens
  IN B AND NOT IN A: tom-opus-r9fix1 (139,931 tokens) dispatched 2026-09-15T06:43:17Z,
    which is 1m31s AFTER his 06:41:29Z return.
```

`22% = 139,931 / 634,125`, and the only repair job in that sum **was dispatched ninety-one
seconds after he came back**. The command that produced it had a lower bound and no upper bound,
and it was run at 07:11.

**The honest overnight figure at the instant he returned is 494,194 tokens over two jobs, both of
them work meant to END the burn — 0% repair, against the 46% he measured the day before.** That
is the same conclusion, arrived at without a number that reaches past his return, and it is what
the report now puts in front of the assistant. The report also says, in as many words, not to
quote a percentage over a window that ends after he is back.

## 3. What it is built from, and why none of it can lie

| the question | the artifact | never |
|---|---|---|
| what did he last say | the transcript, `origin.kind == "human"` and `promptSource != "sdk"` and not `isMeta` | a summary, a recollection |
| what did it cost | the host's own `<subagent_tokens>` in the task notification | an estimate |
| did it land | the integration branch's **reflog**, cross-checked by `merge-base --is-ancestor` | `runtime_state`, `<status>`, the registry's `disposition` |
| what landed | `git log --since --until` per repository | a count from memory |

### 3.1 The trap named in the brief, and the one inside the remedy

The brief warned that `ecs task-status`'s `runtime_state` records the last observed event and not
the outcome — it read `launched` on 19 jobs, all of which had landed. **This uses no status field
of any kind.** The `<status>` from the task notification is carried as "the host said" and decides
nothing; a workspace-registry `disposition` is QUOTED beside git's verdict (`[registry claims
landed: …]`) and never becomes it. `LO24` pins that, and `claim-becomes-verdict` proves `LO24`
can fail.

**But the obvious git check is also wrong, and it fails in the direction that looks right.**

```
$ git -C /Users/alex/ab/richos for-each-ref --format='%(refname:short)' refs/heads/ \
    | grep -E 'silent1|vdesign1|derive1|r9fix1'
(nothing)
```

Every branch from that night is gone: the land sequence merges and then deletes. So
`merge-base --is-ancestor cc/<name> main` answers "no such branch" for **exactly the work that
succeeded**, and a report built on it would have reproduced the 19-jobs error with git's
authority behind it.

The **reflog survives the deletion** and is the artifact:

```
$ git -C /Users/alex/ab/richos reflog show main --date=iso
de525f19 main@{2026-09-14 22:46:23 +0100}: merge cc/zach-opus-silent1: Fast-forward
e6b54777 main@{2026-09-14 23:29:45 +0100}: merge cc/sage-opus-vdesign1: Merge made by the 'ort' strategy.
2545d7f1 main@{2026-09-15 01:09:44 +0100}: merge cc/tom-opus-derive1: Fast-forward
```

Two facts, never one: **the reflog names the merge AND the commit is still an ancestor of the
tip**, because a reflog entry alone can name a commit a later reset discarded (`LO23`). And where
neither holds, the verdict is the words **NO TRACE — "this is 'not seen', NOT 'not landed'"**
(`LO22`). An honest "I cannot see it" is the one answer that cannot mislead.

### 3.2 Which messages are his — derived, not assumed

Over all 766 transcripts on this machine, every distinct provenance of a text-bearing `user` row:

```
  2047  kind=human   src=typed                meta=False   <- HIM
  1348  kind=task-notification  src=system    meta=False
   683  kind=<null>  src=sdk                  meta=False
   443  kind=<null>  src=None                 meta=True    "Continue from where you left off."
   229  kind=<null>  src=None                 meta=False   <command-name>/exit</command-name>
    74  kind=peer    src=system               meta=True    another session's agent
    73  kind=human   src=sdk                  meta=False   a harness driving a session
    53  kind=human   src=queued               meta=False   <- HIM, typed while busy
    24  kind=human   src=suggestion_accepted  meta=False   <- HIM, one click
    14  kind=<null>  src=system               meta=True    fallback wakeup
     9  kind=task-notification  src=sdk       meta=False
```

`queued` is the one a hand-written predicate drops, and it is him typing while the assistant is
mid-turn — which he does constantly; on this very morning he sent the same message twice in forty
seconds. `LO02` pins it and the `typed-only` mutant proves it load-bearing.

**Most `user` rows are not the user.** Count them and the nine-hour gap reads as minutes and
nothing fires at all — `LO12` is that exact shape, built from the real gap's contents.

### 3.3 The arriving message is excluded by identity, never by timing

Whether the host has already appended the arriving prompt when `UserPromptSubmit` fires is not
knowable and not stable across host versions. So nothing here guesses: the hook passes the prompt
TEXT and a trailing human row that matches it, within 180 s, is dropped. `LO13` is the host
ordering where the row is already there; `LO14` is the ordering where it is not; **the answer is
identical either way**. `LO15` is the third arm — a recent message that is NOT the prompt is kept,
so a timing-based rule cannot invent a nine-hour gap thirty seconds after he spoke.

## 4. It is not a guard, and it reaches the model

**It refuses nothing.** No exit code anybody clears, no acknowledgement line, no way to hold a
turn. Every path exits 0, and `LO40` asserts it. The standing rule that a new guard costs a
deleted one does not apply, because there is no guard here.

**The channel is `additionalContext`, and that is the measured one.** From the table carried
verbatim in every rooted hook of this engine (Claude Code 2.1.270, macOS, 2026-09-14, one probe
hook per channel on five events, read back from the transcript):

```
channel, exit 0     SessionStart  UserPromptSubmit  PreToolUse  PostToolUse  Stop
stderr              silent        silent            silent      silent       silent
stdout, plain text  model         model             silent      silent       silent
{"systemMessage"}   PERSON        PERSON            PERSON      PERSON       PERSON
additionalContext   model         model             model       model        model
```

The report goes to the **model**, which is what has to act; the person gets one line. A report on
`systemMessage` is precisely how a staleness notice named a dead guard all day while nobody acted
on it. `LO42` and `LO43` are the two halves, and `wrong-channel` proves them.

**It fires on a GAP, not only at session start**, which is the requirement a SessionStart-only
report would have failed: this session ran 33 hours across three of his sleep cycles and would
have been told once, on the 13th. `LEFT_OFF_GAP_MINUTES=120` is measured rather than chosen — over
the 42 transcripts holding two or more of his typed messages, 1946 intervals:

```
  >=  45 min  202 (10.4%)     >= 120 min  104 (5.3%, 2.48 per session)
  >=  90 min  131 ( 6.7%)     >= 180 min   79 (4.1%)
```

So it speaks about twice a session, and a coffee break is not a return. The gap it was built for
was 9h 01m.

**Why a new file rather than a line in an existing one**, since the brief asked for that
preference and it is the right preference. Seven hooks run at `SessionStart`; exactly **one** runs
at `UserPromptSubmit` — `commit-ceo-inputs.sh`, an ingress whose body is git side effects and
refusal gates. Putting an unrelated predicate inside it, on an event it was never written for,
would be worse than a new file. What IS reused is the substantive half: repository discovery and
the integration-branch question come from `unlanded-branches.py` and `workspaces.py` unchanged, so
there is **no second answer to "has this landed"** anywhere in the engine.

## 6. What is proven, and how

`scripts/hooks/left-off.test.sh` — **38/38**. Every firing case is paired with a silent one built
to be as similar as possible, one fact changed.

`scripts/hooks/left-off.mutation.sh` — **20/20 properties proven load-bearing**, run by the suite
itself. Each mutant removes ONE property from a throwaway copy of the engine and the harness
demands that the SPECIFIC named case goes red:

| mutant | kills | what would happen without the property |
|---|---|---|
| `typed-only` | LO02 | messages he queued while the assistant was busy stop being his |
| `ignores-origin` | LO05 | a task notification anchors the report |
| `ignores-meta` | LO06 | hook feedback closes the gap; nothing ever fires |
| `anchor-is-oldest` | LO30 | the report opens on the first message of the sitting, not the last |
| `no-threshold` | LO11 | a full report under every message |
| `keeps-current-prompt` | LO13 | the gap measures zero on one host ordering; the mechanism is inert |
| `drops-by-timing` | LO15 | a nine-hour gap invented thirty seconds after he spoke |
| `no-reflog` | LO20 | every landed-and-cleaned job reads NO TRACE |
| `trusts-reflog-alone` | LO23 | work that was reset away reads LANDED |
| `sees-the-future` | LO25 | a replay answers with knowledge the instant did not have |
| `claim-becomes-verdict` | LO24 | the registry's word becomes the outcome — failure type 61 exactly |
| `no-trace-reads-as-not-landed` | LO22 | "not seen" reported as unlanded work |
| `no-dedup` | LO32 | repeats crowd out the message carrying the number |
| `no-budget` | LO34 | the host drops the whole object when there is most to say |
| `wrong-channel` | LO42 | the report reaches the person and never the model |
| `repeats-every-message` | LO44 | 6 KB under every message; the channel gets muted |
| `silent-standdown` | LO47 | the report is off and looks like a clean session |
| `silent-unreadable` | LO48 | a broken install looks like a session with no gap |
| `reads-stdin-at-session-start` | LO49 | SessionStart hangs on an inherited pipe (the measured 92 s) |
| `no-transcript-discovery` | LO50 | SessionStart can never find a transcript; silent on the morning after |

**Three defects were found by the suite in the shipped code and fixed, rather than worked
around:**

1. **The hook could exit non-zero.** A bash `EXIT` trap whose last command fails takes the shell's
   status with it, so `_cleanup`'s bare `[ -n "$X" ] && rm` returned 1 on the path where there was
   no temp directory. A hook whose contract is "always 0" was not always 0.
2. **The budget dropped the wrong thing first.** The first version trimmed his sitting before my
   own last reply and threw away the 21:03 message carrying `46% of tokens` — the single number
   the report exists to put in front of the answer. His words now go last.
3. **The suite's own clock was wrong in the direction that hides the bug.** Fixture timestamps
   from the incident made every git case fail, because the analyzer was RIGHT: a replay refuses
   reflog entries written after the instant it reproduces. Fixed by moving the fixture's clock,
   never by weakening the check — and `LO25`/`LO26` now pin both directions.

## 8. What this does NOT do, said here rather than engineered around

- **It does not classify the jobs.** It puts the titles and the token costs in front of the
  assistant and says the split is the assistant's to make. A mechanism that sorted "repairing the
  apparatus" from "work that ends the burn" would be guessing at intent from a description
  string, and it would be wrong silently.
- **The reflog is local and expirable** (90 days by default). Past that, a landed-and-deleted
  branch becomes NO TRACE — which the report says in those words rather than calling it unlanded.
- **It sees only repositories this session touched**, from three unioned sources. A teammate who
  worked somewhere none of them name reads NO TRACE, correctly.
- **The degraded predicate is announced.** On a host that stops emitting `origin`, a wider
  fallback decides, and the report says so and tells the reader to check the transcript directly.
