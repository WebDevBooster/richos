SIGNING: ad-hoc. What that costs, every time:

  An ad-hoc bundle embeds no designated requirement, so macOS stores the raw
  code hash as the identity of every permission it grants — and nothing else.
  The moment this build differs by one shipped byte from the installed one, it
  is A DIFFERENT APPLICATION to macOS: microphone and accessibility grants
  start at zero, and toggling the switch in System Settings provably does not
  migrate a grant (measured 2026-08-24, richos-hq/wiki/packaging-and-signing.md).
  Voice mode and paste-at-cursor will need granting again after installing this.

  Measured here 2026-08-30, because the distinction matters: what moves the
  hash is the BYTES, not the act of rebuilding. Three consecutive runs of this
  script over an unchanged tree — and one over a tree whose only edit was dead
  code the optimizer removed — all produced cdhash fc5051ac…, i.e. the same
  application and a surviving grant. Changing ONE shipped string moved it to
  27a561ef…. So this is not a tax on rebuilding; it is a tax on every change
  you would actually ship.

  The fix is a Developer ID certificate. The MEMBERSHIP that gates it exists as
  of 2026-08-31 (CEO decision 1.1, closed); the certificate is a separate step.

  LOUD NOTE: this machine has 1 Developer ID Application identit(y/ies), so
  a signed build IS possible now. It was NOT used, because nothing asked for
  it. Re-run with --sign developer-id (the identity is discovered).
