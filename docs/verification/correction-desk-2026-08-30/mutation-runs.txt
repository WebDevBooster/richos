THE CORRECTION DESK — THE SEVENTEEN RUNS THAT PROVE THE SUITE CAN FAIL
======================================================================

`app/ui/tests/corrections.js` reports 18/18 and 71 assertions against the tree as it
stands. That number is worth nothing on its own: a check that has never failed has proven
nothing, and this repository has produced both kinds of green in one week — a scanner
reporting CLEAN over an empty corpus, and a `run.js` reporting "all 4 suites passed" over a
suite it was not running.

So every check in the suite was run RED, once, by breaking the thing it guards in the
SHIPPED source (`app/ui/main.js`, `app/ui/style.css`, `app/ui/mock.js`,
`app/src-tauri/src/main.rs`) and watching the suite say so.

The driver applied exactly one edit per run, refused to proceed unless the target string
matched exactly, restored the file from a copy taken before the edit whether the run
passed or failed, and `git status` was clean at the end. It is
`scratchpad/mutate.py` from the session that produced this file; the mutations are also
listed inside `corrections.js` itself, against their check numbers, so the two cannot
drift silently.

THREE OF THESE DESERVE A NOTE
-----------------------------

  * MUTATION 6b, FIRST ATTEMPT, WAS A BAD MUTATION AND IS RECORDED AS ONE. Replacing
    `if (st.available) st.readFailed = String(e);` with a bare `st.available = false;`
    left the `else st.offReason = String(e);` beneath it with no `if`, so `main.js` did not
    parse and all seventeen checks went red. That is a red run, and it proves nothing about
    check 6b. It was redone surgically as `if (false) st.readFailed = …`, which keeps the
    file parsing and produces the actual defect — a transient read failure reported as an
    uninstalled desk — and turned exactly one check red. The first attempt is left in this
    transcript rather than deleted: a mutation that breaks everything is the mutation-
    testing equivalent of a green run over an empty set.

  * MUTATION 3 (dropping the `loro_confirm_correction` invoke) turns check 3 AND check 7b
    red, which is the argument for 7b existing separately. Check 3 alone would have stayed
    green under the OTHER confirm mutation — announcing "Done." without reading
    `done.state` — because the write really did land in that fixture. It is 7b, driving a
    writer refusal, that catches a surface reporting a refused write as done, and that is
    the single outcome most likely to make the CEO stop correcting things.

  * MUTATION 5-hidden turns check 9b red as well, and correctly: 9b asserts that after a
    permanent decline the suppression list is STILL ON SCREEN explaining the silence when
    the same pair repeats. Hiding the block removes the explanation, which is exactly §7's
    "a term silently refuses to learn with no way to see why".
