# The loro correction trigger, measured — 2026-08-30

**Nothing in this directory is private.** Every sentence AND every record measured here was
invented for the measurement and is written out in full in
[`corpus/utterances.json`](corpus/utterances.json). No transcript of anyone appears, no line here is
a real spoken sentence, and no record is a real loro record — the corpus is not in this repo and
never will be. Every person, company, place and figure is fictional; the only non-fictional terms
are `Deepgram`, `whisper.cpp`, `Postgres` and `MySQL`, which already appear in the public wiki as
the doctrine's own worked examples.

---

## What was open, and what closed

The correction desk landed on 2026-08-29 and its surface on 2026-08-30 (`bd62126`). Both halves are
right, both are tested, and `wiki/loro-writer.md` names what was left:

> **One real gap remains:** nothing DETECTS a loro correction — something has to propose, and that
> trigger is unbuilt, so this desk is empty on a real machine until it exists.

`app/crates/richos-core/src/correction.rs` says it from the other side: *"It does not detect
corrections. Nothing here watches for 'that's wrong' and files a proposal on its own … that trigger
is named as unbuilt rather than faked."* `CorrectionDesk::propose` had exactly one caller in the
product — the Tauri command `loro_propose_correction` — and nothing invoked it.

This measures the trigger that closes that.

## The result

```
  SHIPPED (topic condition ON)   TP 34  FP 0  FN 1  TN 112   precision 1.000   recall 0.971
  COUNTERFACTUAL (topic OFF)     TP 34  FP 12  FN 1          precision 0.739   recall 0.971
```

147 invented utterances: **35 corrections, 112 negatives, 105 of the negatives carrying a standalone
`not` pivot on purpose**, and the great majority of those naming a value that IS on one of the
records. The negatives are adversarial rather than representative, so the precision is a **lower
bound** on precision in use; recall is unaffected by the imbalance.

Full table: [`results/precision.txt`](results/precision.txt). It is regenerated by the test that
pins it, not written by hand:

```
cargo test -p richos-core --test belief_precision -- --nocapture
```

## Scoring, and why it is strict about the ref

**A proposal is a true positive only if the ref, the rejected side and the asserted side are all
right.** A proposal with the wrong ref is scored a FALSE POSITIVE, not a partial hit. The ref names
the record that gets superseded, and a proposal against the wrong record is a corruption the CEO
would have to catch by reading `--dry-run` bytes — which is the failure this whole design is
arranged around.

## What the counterfactual decides

The second line is not decoration. **"A correction must NAME what it corrects"** — the condition
that the utterance and the record share a content word — is the single condition doing the most
work, and the table says by how much: turning it off leaves recall untouched at 0.971 and takes
precision from **1.000 to 0.739**, because twelve negatives name a value that is on a record while
being about something else entirely:

> *"Let's meet in March, not February."* — the renewal record says February. Without the topic
> condition, that sentence supersedes the Halstead renewal with a sentence about a meeting.

That comparison is itself an assertion in the test, so if a future change ever makes the condition
free, the claim that it is not fails rather than this paragraph going quietly stale.

## The one condition that earns nothing here, kept anyway

Removing the routing to the vocabulary desk — *"the two sides are one name spelled two ways, so
this is a mishearing and belongs to `staging.rs`"* — leaves the matrix at **34/0/1/112 exactly**.
The eight mishearing negatives are already refused by the topic condition or by "the record already
states this", so on this corpus that condition removes zero false positives.

It ships anyway, and its keep is **doctrine rather than measurement**: one utterance must never
reach both desks, or the CEO is asked twice about one sentence and two desks disagree about what he
meant. A unit test holds it, not this table — and this section exists so the corpus's number is not
quietly claimed for it.

## The one miss, named

`c22` — *"Priya Nair owns the Halstead account, not Marcus Webb."* The asserted name sits at the far
end of its clause behind the article `the`, which stops the span scan (the same structural rule the
vocabulary trigger uses), so the extractor offers `Halstead account` instead of `Priya Nair`. The
"record already states this" condition then refuses it. **The system misses safely rather than
proposing wrongly**, which is the trade this surface is supposed to make. Its mirror image —
*"The Halstead account owner is Dana Okonkwo, not Marcus Webb."* (`c23`) — is found.

## And it still asks

A precision of 1.000 measured by the author of the corpus is evidence about the SHAPE of the errors,
not a licence. Nothing here writes: the detector returns candidates, `CorrectionDesk::propose` runs
the loro writer with `--dry-run` and stores what WOULD be written, and `confirm` — a human answer —
remains the only path to a loro write. `ceo-decisions.md` §7: *"Nothing is ever learned silently."*
