# turbo vs q5_0 — the model-choice rig, 2026-09-10

Companion to [`whisper-model-choice.md`](whisper-model-choice.md), which is the table this rig
exists to fill in. Read that first; this file is how the numbers in it were produced.

**This is a MEASUREMENT, not a recommendation.** Nothing here changes a default, and no row below
argues for one model. Open item 1.3 — `large-v3-turbo` or `large-v3-turbo-q5_0` as the shipping
default — is not decided in this directory.

## Its relationship to the settings rig beside it

[`../whisper-settings-2026-09-10/`](../whisper-settings-2026-09-10/) settled every `whisper-cli`
flag on `large-v3-turbo` and pinned the toolchain. Its §6 says the one row that could plausibly
differ for a quantized model is `-fa`, because flash attention interacts with numeric precision,
and that if the default moves to q5_0 the `nofa` row should be re-run and nothing else.

So this directory:

- re-runs that `-fa` row on q5_0, **and on turbo in the same sitting**, because a delta measured
  against a baseline from another corpus render is not a delta;
- puts the two models head to head under the settings **as they now ship** (`-mc 0` pipeline-wide,
  `-fa` explicit) — every earlier turbo-vs-q5_0 comparison predates both;
- does it on the long real recording as well as the short calls;
- measures peak memory and wall clock instead of quoting the tier table's 2026-08-26 figures.

**It reuses that rig's tools rather than reimplementing them** — `flag-sweep.mjs`,
`longform-decode.mjs`, `guard-report.mjs`, `name-hits.mjs`, `whisper-argv-shim.sh` are all imported
by path, so a decode measured here is the same instrument that produced the settings table. Four
tools are new, and only because that rig had no way to answer these four questions.

## The three new tools

| File | What it does, and why it did not already exist |
|---|---|
| `tools/whisper-rss-shim.sh` | Records the peak memory of the decode process. The settings rig records argv; nothing recorded memory, and the tier table's RAM figures are from a different binary, a different decode configuration and an 11-minute sample. Chains BEHIND the argv shim so a run stays self-witnessing. |
| `tools/shortcall-guard.mjs` | Runs the SHIPPING repetition guard over a whole short-call sweep, and scores WER on **both sides of it**. The settings rig adjudicates fabrication only at 92 minutes, because at call length it had not appeared. It appears here. |
| `tools/model-table.mjs` | Renders every table in the record from `measurements/raw/`, so the figures are generated rather than transcribed cell by cell. |

The text inspection behind `measurements/fabrication-case.txt` — post-guard transcript, guard
verdict and phrase counts for one call — is quoted verbatim in that file rather than kept as a
fourth tool, because it is one call, once, and a tool implies a sweep nobody ran.

## The corpora, and the one thing this rig adds to them

Same permanent material as the settings rig — its README enumerates all of it, and there will be no
new recordings. What is added here is a **second render of the short-call corpus**.

The settings rig established that `say` output drifts between renders and that absolute WER is
therefore comparable only within one sitting. It did not establish whether a **difference between
two configurations** survives a re-render. This work needed that, because the headline short-call
number turns out to move by more than the model gap it is being used to measure. So the same script
is rendered twice, independently, and both models are run on both renders:

| | concatenated sha256 of the 12 channel WAVs | bytes |
|---|---|---|
| render A | `8b7820f83784111389e0b0189c0ac75381dfe4021fea908382f6da2cf38d1f9d` | 45,259,468 |
| render B | `c5835b78b4c1709f9600b130c848b3fc44f108bf7c7312d851ce01ab5a8a7ae4` | 45,259,400 |

**The first version of that check was broken and the record says so rather than hiding it.** It
hashed render B immediately after `build-corpus.mjs`, before `normalizeSession()` had written any
`.wav`, so it hashed nothing and returned
`e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855` — the sha256 of empty input —
while printing "different bytes — independent render confirmed". A check that cannot fail is not a
check. It is re-run after both sweeps in `measurements/rig-facts.txt`, where the digest of empty
input is printed alongside for comparison.

## Results

| File | Holds |
|---|---|
| `measurements/model-comparison.txt` | every table, generated by `tools/model-table.mjs` |
| `measurements/name-hits.txt` | proper-noun exact hits, both renders |
| `measurements/fabrication-case.txt` | the one finding that is not a rounding difference |
| `measurements/rig-facts.txt` | stack identity, model hashes, integrity-hash cost, corpus digests, channel speech share |
| `measurements/raw/` | per-run `summary.json`, `rows.json`, `argv.jsonl`, `rss.jsonl`, guard reports |

Every configuration's `argv.jsonl` records the real command line that produced its numbers, and
every one has a `rss.jsonl` beside it recording the peak memory of that same process. A results
file whose argv does not contain the flag it claims to be testing is a broken measurement.

## Reproducing

Step 1 needs the private record, exactly as the settings rig documents — the corpus builder, the
reference script and the `wer.mjs` scorer live in
`richos-hq/docs/briefs/norm-shortcall-wer-2026-08-29-assets/`, and the real recordings live in
`richos-hq/docs/reference/local/`, gitignored and committed nowhere.

```sh
# 1. build the corpus (twice, into two directories, for the render-stability pair)
node <hq>/.../tools/build-corpus.mjs <hq>/.../corpus/calls.json /tmp/corpusA

# 2. one short-call configuration, with BOTH shims chained
export RICHOS_WHISPER_REAL=<here>/tools/whisper-rss-shim.sh
export RICHOS_WHISPER_RSS_REAL=$(command -v whisper-cli)
export RICHOS_WHISPER_RSS_LOG=/tmp/sweeps/q5.rss.jsonl
node ../whisper-settings-2026-09-10/tools/flag-sweep.mjs \
  --lib <richos>/tools/richos-service/lib --corpus /tmp/corpusA --out /tmp/sweeps \
  --wer <hq>/.../tools/wer.mjs --config q5 --model large-v3-turbo-q5_0 --extra ""

# 3. fabrication + WER either side of the shipping guard
node tools/shortcall-guard.mjs --lib <richos>/tools/richos-service/lib \
  --sweeps /tmp/sweeps --corpus /tmp/corpusA --wer <hq>/.../tools/wer.mjs

# 4. long form, per channel, per model (guard-report.mjs from the settings rig adjudicates)
node ../whisper-settings-2026-09-10/tools/longform-decode.mjs \
  --lib <lib> --wav /tmp/real/me.wav --channel me --out /tmp/real/runs \
  --config q5 --model large-v3-turbo-q5_0

# 5. regenerate every table in the record
node tools/model-table.mjs --raw measurements/raw
```

`RICHOS_WHISPER_RSS_REAL` is not optional when the shims are chained: `RICHOS_WHISPER_REAL` then
names the RSS shim, and without the second variable the shim's exec target would be itself. It
refuses that by name rather than forking.
