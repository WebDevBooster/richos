## Conflicts and integration fixes

Seven files conflicted. Both branches had improved the UI source inventory,
contrast coverage and affordance checks independently. The resolution retains
main's updater, additional surfaces and coverage-boundary checks alongside the
assignment panel, its source-discovery negative controls and all seven assignment
contrast surfaces. Both CSS additions are retained. README test counts were
recomputed from the combined source, including the distinction between direct
core tests and two fixtures invoked only by their parent tests.

Two behavioral issues needed correction beyond resolving Git markers:

- Main's updater knew about conversation turns and workers belonging to that
  conversation. Durable work runs separately. The updater now also checks the
  ownership slot, registration handoffs and saved unfinished assignments before
  offering or performing an update. This includes the gap before intake writes a
  registration request, retry waits and paused assignments. Completed or canceled
  assignments do not block it. A missing or unreadable record yields uncertainty
  and makes the update wait. The update checks use a nonblocking spine lock.
- The desktop decision harness caught a scope change that execution retained but
  the human display projection no longer showed. The view now projects exact
  instruction changes from structured, saved decision receipts. History labels
  them **Your updated instructions**. The fix does not parse machine prompts to
  reconstruct the CEO's answer. Native checks verify both the displayed correction
  and its presence in the execution prompt and verifier input.

The updater's state is initialized before the owned-work desktop selftest starts.
The new updater phase checks a clear baseline, unfinished and paused work,
registration waiting, an active writer, unreadable input and return to clear. Its
12 checks are counted as they execute. The enqueue phase also checks the gap
between a completed conversation turn and persisted registration.
